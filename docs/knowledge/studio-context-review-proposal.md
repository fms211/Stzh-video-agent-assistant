## 审查范围

由一名未参与实现的原生子Agent，以新上下文只读审查当前四模式的上下文边界。审查不修改文件、不运行媒体生成、不读取环境密钥、不查询用户私有会话，也不调用项目配置的外部模型或付费API。

独立审查只判断代码和本地证据能否支持边界结论；不等同于实际产品模型输出的盲评分，也不能据此开启enforce或宣称P95延迟、成本、回答质量达标。

## 独立问题与交付

1. 每一模式实际用什么内容检索记忆，历史、前序产物及外部来源会不会扩大当前用户任务？原始输入缺失时是否说明限制？
2. 用户确认、引用内容、服务端已保存的结果与运行完成/审批分别由什么证据支持？是否存在把参考材料升级为状态或指令的路径？
3. 账户、项目、会话、运行及来源版本如何核验？排除、删除、失效来源和并发更新是否可能被缓存或重放重新引入？
4. 按完整协议预算时，哪些内容必须保留？Coze远端未知历史、容量未知及超预算能否被错误宣称为已受控？
5. 中断、同步失败、模型已消费但响应丢失时，应从哪里确认实际结果？哪个环节可以安全重试，哪个仍未知？
6. 当前证据还有哪些薄弱处？只报告可定位到具体路径与触发条件的问题，并区分代码缺陷、证据不足和需要外部环境的门禁。

交付格式：逐模式结论、可定位的风险、必要的最小修正与验证方法。没有发现缺陷也须列出未覆盖的运行条件；报告不得将这份方案表述为已完成审查。
