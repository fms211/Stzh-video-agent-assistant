# 创意工坊记忆 API v1

最近核验：2026-09-30。本阶段提供真实HTTP/SQLite生命周期与检索；四模式请求、记忆管理和来源展示已接线，默认shadow，仅预览上下文，单次是否应用以contextTrace.applied为准。旧 `opc_memory` 键值表和进程内 `opc-memory.ts` 不自动迁移；保留原始会话和运行记录。下文带日期的开发段落保留当时进度，当前汇总见阶段四逐项验收矩阵。

## 身份与存储

所有端点位于 `/api/studio/memories`，要求当前账户JWT并返回 `Cache-Control: no-store`。身份由鉴权中间件提供，body中的owner、status、verification等只读字段直接拒绝。

- `studio_memories` 存账户、稳定ID、revision、JSON契约和时间，有账户/ID索引；每账户最多1000条，正文最多4000字符。
- `studio_memory_requests` 保留账户、请求键hash、请求payload hash与创建ID。与记忆插入同一事务，避免半条保存。删除正文后仍保留该映射，防止迟到的同一保存请求复活记录；不保存正文、密钥或原始请求键。
- 检索已接入可重建的FTS5候选索引，再动态核验账户、范围、来源和版本后进入公共排序；具体索引规则见下文9/28接线与性能核验。当前不使用向量索引，仍保留每账户1000条的容量边界；生产规模及真实模型质量需单独验收。
- 工作记忆默认1小时有效期；显式expiresAt可覆盖。过期条目不注入，但仍可管理/导出/删除，不自动删除用户原记录。

## 端点

| 请求 | 输入 | 结果 |
|---|---|---|
| `POST /` | requestKey、mode、content；可选scope/kind/claimKind/importance/expiresAt/slot/source | 201新建candidate；相同请求键及内容返回200与当前记录 |
| `GET /?limit=50&after=…` | limit 1–100，after为上页nextCursor | 当前账户记忆、sourceAvailable、nextCursor；按稳定ID排序 |
| `GET /:id` | ID | 当前账户记录，不存在或属于其他账户时404 |
| `PATCH /:id` | expectedRevision及content/scope/importance/expiresAt/slot/enabled | revision递增；正文、scope或slot改变时重新candidate并清空核验结论 |
| `POST /:id/confirm` | 仅expectedRevision | status改为confirmed；不改变verification，不自动重新启用停用记录 |
| `DELETE /:id` | 仅expectedRevision | 204删除正文；后续GET404，原保存请求重试410 |
| `GET /export` | 无 | schemaVersion、exportedAt及当前账户全部存储记录；含候选/停用/过期记录 |
| `POST /search` | query、mode；可选projectId/sessionId/runId/currentConstraints/limit | 公共层selected/dropped/retrievalVersion；只检索，不调用模型 |

模式名为 `coze/assistant/workflow/collaboration`。重要性0–1。scope为user、project或带mode的session/run。当前支持Coze会话、助手/普通工作流会话、研究run和协作run；不伪造其他模式不存在的run实体。

同requestKey不同输入返回409；已删除记录对应requestKey返回410。输入/版本错误400，版本变化409。新建总为candidate，需要独立confirm。patch不能伪造来源或核验状态；expiresAt和slot允许null清除。单独停用或删除允许在来源已撤回/过期之后执行，以便用户管理失效记录。

正文中的明显访问令牌格式和非normal敏感标记不允许作为长期记忆。这个有限格式检查不等于完整敏感信息识别；调用方仍须遵守不保存敏感内容的默认规则。

## 来源与范围

9/30补充会话目录契约：GET /api/opc/sessions 仍按鉴权账户查询和分页，mode返回chat/workflow/coze；chat对应记忆范围中的assistant。目录复用studio-session-scope的模式登记及兼容解析，避免Coze统一存储被当成助手。客户端合并同步时以服务端mode纠正旧分类，同时保留较新的本地标题等信息。真实HTTP和缓存合并回归已覆盖；本批不新增模式表或数据库迁移。

未提供source时，由服务端写入 `manual:<memoryId>`，只表示本账户手动记录。客户端不能伪造另一个manual入口。

提供source时需含mode与recordId：

- 会话来源同时带sessionId，服务端验证真实账户、模式及消息属于该会话。
- 运行来源带runId，recordId必须是该runId；研究artifactIds必须出现在该账户该运行快照中。协作run不接受研究artifactIds。
- 每次检索重新确认scope、来源与产物可用性；删除源消息/撤回产物后即不再参与检索。
- research/collaboration查询给出runId时，从权威run派生projectId；若显式项目不一致则拒绝。projectId本身也需当前账户所有权。

当前项目模型只有owner，没有新增成员共享权限。来源可读只证明可引用，不证明用户提交摘要与原文一致；因此API始终保留unverified。来源内容的版本变动/事实核验还需后续证据系统，不能自动把这些条目当成运行事实。

### 9/28 候选记忆与统一会话模式（开发中）

新增studio_session_modes明确标记统一opc_sessions中的Coze/助手/工作流会话；旧conversations/messages仍作兼容来源，不能把当前Coze统一存储误判为助手。候选和摘要的来源检查共用模式/归属解析，Coze账户适配器同时检查新旧存储的实际owner。通用会话写入注册模式与会话变更处于同一事务；已有模式不被别名路由覆盖。消息ID跨会话冲突409，避免INSERT OR REPLACE覆盖其他会话的来源。

消息同步识别显式“记住：/请记住：”文本及工作流action-cards，协作形成待确认草稿、研究保存完整产物后生成带来源的候选。全部candidate/unverified，不自动恢复停用条目，不因用户陈述升级事实；普通聊天和“不要记住”不触发。采用固定规则，无额外模型调用，不声称推断了所有隐含偏好。短结果保留完整原文，超长结果仅记录可回查来源的事件说明，不截断成片面结论。重复同步同请求不重建，删除候选后重试不会复活。

候选生成在主消息/运行已保存之后独立执行，失败单独记为skipped，不将成功主操作改判失败。候选不在模型调用中直接使用，需用户在记忆管理中核对、编辑范围和确认。旧工作流模块内存中的高置信度截断摘要写入已移除。50项受影响的来源/模式/摘要/研究/候选边界检查通过，浏览器与最终全量回归仍待集中执行。

### 9/28 非破坏性摘要与按需原文（开发中）

`studio-summary-store.js`独立存储摘要版本、消息范围、每条来源指纹及生成方法。extractive-v1按相关性与新近性选择至多6条完整原文、正文合计3000字节；超长消息保留引用而不截断否定/限定语。它是历史摘录，不是语义归纳或已验证事实总结。缺失原文可按20条分页读取。摘要建立不触发任何模型调用。

`POST /api/studio/summaries`接受mode/sessionId/query/keepRecent；GET `/:id`返回current/stale；GET `/:id/sources`对账户、会话及全部来源指纹重新核验，变化后409要求重建；DELETE `/:id`仅删摘要，不删会话。相同覆盖范围、内容与算法复用摘要，变化时生成新版本。每账户上限1000摘要，单会话本版最多2000条；超过范围显式失败，不静默宣称全量覆盖。

### 9/28 来源版本与精确整合（开发中）

来源记忆新建时由服务器读取并记录SHA256 fingerprint，客户端不得指定。每次检索重新计算消息正文/元数据、协作任务及结果、研究产物内容的指纹；变化或旧记录缺指纹时停止注入。手动记忆维持原行为。来源仍可读不等于版本仍有效，响应分别提供sourceState（manual/current/changed/untracked/unavailable）和sourceAvailable。

GET `/:id/source` 返回账户内来源预览、指纹和截断标志；POST `/:id/refresh-source` 必须携带expectedRevision和expectedSourceFingerprint，两者任一过期都拒绝。成功仅更新来源绑定并重置candidate/unverified，原记忆正文不自动改写，核对/编辑后再确认使用。UI支持查看与重新待确认。预览最多20000字符，版本计算使用完整内容。

不同requestKey但来源版本、正文、scope、类型、参数及有效期完全相同的记录复用同一ID，并将新请求键映射到该记录；不会恢复已停用记忆或提升核验状态。内容冲突不自动合并，来源新版本不与旧版本合并。删除后旧请求键仍返回410。此为精确来源整合，不是语义归纳；自动候选/摘要仍待实现。

### 显式否定与检索质量边界

检索器`creative-lexical-v6`在查询明确拒绝、把旧风格改成新风格、从旧值换成新值、旧值不要了或换掉旧值时，不再因旧词项把肯定表述的旧偏好选入本轮。候选整体含被当前输入拒绝的内容时，即使其他正向词匹配，也不注入该候选。高/低对比、浅/全景深等已识别概念分别核对查询及候选的否定极性，否定项不被当作正向偏好；普通比较仍可引用两种方向，兼容的否定约束可以保留。这是有限的词法规则，不覆盖任意自然语言否定。SQLite FTS只负责召回候选，最终服务端选择再次应用否定、权限、当前结构化参数及预算规则。FTS词项编码未变，索引版本维持`creative-lexical-v3`，本次无需按账户重建；以后词项编码变化才更新索引版本。
