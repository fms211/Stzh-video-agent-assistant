## 背景与目标

在前一批真实文件仓库、安装预览与子进程宿主基础上，把正式插件页面接到服务端，并验证用户能够从浏览器完成安装、启用、安全模式和回滚。图片/视频额度与成片效果按用户要求继续暂缓，本批次不调用生成模型。

## 用户可感知变化

1. 插件中心正式入口改用 HTTP Adapter，不再读取演示安装包和演示项目。
2. “从来源安装”可以选择 npm、GitHub 或本地 ZIP/.stzhplugin；本地选择后真实上传，进入原安装预览与确认流程。
3. 项目选择器显示账户真实项目名称，并可新建项目。
4. 可以在项目中启用、禁用、固定版本、解除绑定、重建、安全模式和回滚。
5. 恢复页面读取真实健康快照、项目事件和隔离记录；无运行时不再显示虚假的健康状态。
6. 网络或服务异常会显示可读错误。运行失败的具体原因会显示在项目状态和恢复页。

### 项目运行与权限

- 新组合逐个启动真实子进程并校验工具注册及健康状态，成功后才切换；启动失败保留原健康组合。
- 安全模式使用空插件组合，保留已保存绑定；回滚恢复指定健康快照的版本、权限与配置。
- 宿主运行期间崩溃或超时会撤下贡献并记为失败；关闭服务会中断正在启动的组合，不能在关闭后发布迟到健康结果。
- 进程重启后保留历史健康快照。页面明确显示停止，需重建后才能调用工具。
- Safe 档仅提供项目与产物读取；Standard 增加文本产物、模型和声明的网络能力；Full 才能请求任务或已配置命令。
- 请求身份从服务端当前账户和项目绑定派生，忽略插件传入的 owner/userId/projectId 覆盖字段。
- 网络能力限制为 HTTPS，核验声明域名与 DNS 公网地址，并固定已核验地址连接；不自动跟随重定向。
- 工具输入/输出按 manifest 中的 JSON Schema 验证。

## 接口/数据/兼容性

新增 `/api/plugins` 下的目录、上传、解析、安装、账户库、绑定、版本、安全模式、回滚、历史、事件、贡献和工具调用接口。新建 `plugin_uploads`、`plugin_artifacts` 表，沿用前一批插件仓库和运行组合表。

上传保留30分钟，单包16MB、每账户最多5个待安装包；文件位置按账户及随机上传标识派生。模型接口的请求封装支持 FormData，保留原有 JSON 调用方式。

前端 Adapter 可选新增上传、解除绑定和健康历史方法，旧 Mock 仍保留为自动测试 fixture；正式 HomeClient 不再实例化插件 Mock。模型与角色页面按账户重建，避免跨账户复用旧表单/列表。

测试服务与网页继续使用 `output/stage4/isolated-data/` 和合成验收账户，主数据库及手机端代码未改变。

## 已知限制与剩余范围

- 带第三方依赖/构建脚本的包仍等待构建执行器接入，当前会明确拒绝而非跳过构建假装成功。
- 插件 UI 资产服务、iframe 权限桥、贡献槽位的实际呈现，以及研究 Tool Registry 接入尚未完成。
- Full 档命令执行需要服务器命令白名单执行器；没有配置时明确拒绝。
- 目录目前无预置第三方条目，安装通过来源入口完成；签名最终以解析预览的实际校验为准。
- 插件项目文本产物可通过 broker 保存/读取，但产物目录与包版本隔离、清理的完整策略仍需继续联调；当前卸载不会删除项目产物。
- 独立模型与真实网络能力尚未使用用户模型配置做端到端验收；权限测试中这些提供商为明确注入的测试实现。
- 安装向导焦点约束、页面响应式和全站最终视觉定版仍在阶段四清单内。
