# 创意工坊重构：移除冗余助手弹窗 + 工作流迁入右侧创意助手

- **状态**：已完成
- **影响范围**：前端「创意工坊」页面、OPC 助手入口、链式工作流执行、模型栈统一
- **分支**：fms-hermes
- **完成提交**：未提交

## 背景与目标

「创意工坊」页面的正确结构此前被误解为「左侧提示词实验台 + 右侧简化聊天助手 + 一个带工作流的弹窗」。实际意图是：

- 右侧「创意助手」（`ModelAssistantPanel`）**就是**原 prompt 实验台的 AI 助手，应承担对话与工作流的全部能力
- 模型配置已统一到「模型与角色」页（服务端 `/api/model-providers`）
- 提示词实验台里那个「AI 创作助手」按钮及其打开的 `OpcAgentPanel` 弹窗是**冗余**的

本次目标是：移除冗余入口、把 6 个链式工作流迁入右侧创意助手、把工作流的模型调用从旧客户端栈统一到服务端栈、删除变成孤儿的组件文件。

## 用户可感知变化

- 提示词实验台**不再显示**「AI 创作助手」按钮（`opc-ai-trigger`），也不再有弹出的 `OpcAgentPanel` 弹窗
- 右侧「创意助手」顶部新增「对话 / 工作流」切换
- 工作流视图展示 6 个链式工作流（创作 1 / 优化 1 / 研究 3 / 脚本 1，分组折叠）
- 选中工作流后显示参数表单，提交即自动链式执行，步骤以 `WorkflowStepCard` 展示，完成后出现 `ActionCards`（保存报告 / 继续讨论）
- 对话与工作流**共用同一个模型**（「模型与角色」页配置的服务端模型），不再依赖旧的 localStorage 客户端模型栈

## 实现内容

1. **移除冗余入口**
   - `OPCPanel.tsx`：删除 `onOpenAgent` prop、`opc-ai-trigger` 按钮及全部相关内联样式
   - `CreativeStudio.tsx`：删除 `OpcAgentPanel` 挂载、`opcAgentOpen` state、以及 6 个仅为回传 `opcContext` 的 state

2. **工作流迁入 `ModelAssistantPanel`**
   - 改为「对话 + 工作流」双模式，复用 `opc-workflows.ts` 引擎（`getWorkflowsByCategory` / `getWorkflowById` / `getWorkflowStepsWithReflection` / `getPlannerPrompt` / `applyDynamicPlan`）
   - 工作流执行引擎内联在组件中：动态规划 → Reflection → 链式多步，每步做 RAG 检索 + 网络搜索增强
   - 复用 `WorkflowStepCard`（步骤进度）+ `ActionCards`（完成后动作）
   - 保留 RAG（`ragRetrieve`/`formatRagContext`）、搜索（`searchAndFormat`）、记忆（`addMemory`）增强

3. **模型栈统一**
   - 对话与工作流的模型调用统一走服务端 `creativeApi("/api/model/chat")`，`providerId` 来自 `/api/model-providers`
   - 摆脱旧的 `llm-config.ts`（localStorage XOR 混淆）客户端栈

4. **删除孤儿文件**
   - 组件：`OpcAgentPanel` / `OpcAgentSidebar` / `OpcAgentChat` / `OpcAgentInput` / `OpcAgentMessage` / `ModelSwitcher` / `ModelConfigPanel` / `QuickActions`（共 8 个）
   - lib：`opc-agent-persist.ts` / `opc-agent-api.ts`（仅被待删组件引用）
   - 保留：`types.ts` / `WorkflowStepCard.tsx` / `ActionCards.tsx`（渲染复用）+ `opc-workflows.ts` / `rag-client.ts` / `web-search.ts` / `opc-memory.ts` / `opc-agent-context.ts`（引擎复用）

## 接口/数据/兼容性

- **无后端接口改动**：工作流复用既有 `POST /api/model/chat`、`/api/model-providers`、`/api/rag/retrieve`、`/api/search`
- **模型栈迁移影响**：工作流不再读 `localStorage` 的旧 `tszh_llm_providers`，改用服务端 `llm_providers` 表（「模型与角色」页维护）。旧 localStorage 模型配置不再被工作流/对话使用
- **无数据库迁移**：删除的 `opc-agent-persist` 只读写本地 OPC 会话缓存，不涉及服务端数据表
