# 可靠任务队列内核与租约 Runtime

- **状态**：已完成
- **影响范围**：服务端 SQLite 任务队列、租约执行内核、隔离测试
- **分支**：`codex/route-b-task-linkage`
- **完成提交**：未提交

## 背景与目标

本次更新先建立服务端可靠任务队列的底层能力，使任务执行由 SQLite 中的状态和租约约束，而不是依赖设备心跳推断。目标是解决原子领取、同账户并发隔离、定时任务、进程崩溃恢复、旧 Worker 防覆写和优雅停止等基础问题，为后续接入真实 Agent Service 做准备。

## 用户可感知变化

本批次没有切换移动端任务执行路径，也没有接入真实 Coze，更没有修改 UI/CSS。桌面端仍沿用原执行路径，但领取后必须持有服务端返回的租约 token，并在进度、完成和失败请求中携带；新增 Runtime 仍只作为可注入的服务端模块存在，未在 `server.js`、Electron 或其他真实启动入口自动启动。

## 实现内容

- 增加幂等 `schema_migrations` 迁移，为 `tasks` 增加 `worker_id`、`lease_token`、`lease_expires_at`、`attempt_count`、`execution_mode`，并建立领取与租约过期索引。
- 迁移前通过 SQLite `VACUUM INTO` 在数据库同目录创建不覆盖旧文件的一致性快照；遗留 `running` 任务仅在首次迁移时恢复为 `queued`，保留输入，其他状态不重置。
- 增加原子领取、60 秒默认租约、高熵 token、续租、进度/完成/失败 CAS、过期租约回收、按 Worker/token 释放租约等数据层能力。
- 旧 `/claim` 兼容路径也纳入同账户有效运行约束：同一账户已有有效 Runtime 或旧设备运行时会明确拒绝第二次领取；成功领取生成独立的 32 字节高熵 token、`legacy:<deviceId>` Worker 标识和 60 秒到期时间。`taskClaimNext` 同时识别 Runtime 和桌面租约，避免双执行。
- `/progress`、`complete`、`fail` 全部要求正确且未过期的 token；正确进度会同时把租约续期 60 秒。缺 token、错误 token、过期 token、暂停后旧 token，以及租约换手后的旧 Worker 请求都安全失败。
- 新增认证续租端点 `POST /api/tasks/:id/lease/renew`：先按登录账户检查任务归属，再验证 token 和活动 expiry；只有仍有效的当前 Worker 能续租，成功返回序列化任务，错误 token 或过期租约返回 `409`，其他账户看不到任务。
- 桌面 `executeTask` 在 Agent 请求期间默认约每 15 秒串行续租一次。续租循环使用“本次 settled 后再安排下一次”的定时方式，不产生重叠请求；成功、业务异常、外部 abort 都会停止定时器并移除监听器。续租失败会中止正在等待的 Agent fetch，且不再提交 complete/fail。
- `taskAction` 的最终状态更新以读取到的 `status + revision + lease_token` 做 CAS；读取后若其他连接已经完成、失败、暂停或换租约，会返回明确 `conflict`，不覆盖新状态。
- 租约回收在逐条更新时重新核对捕获的 revision、token、Worker、旧设备与到期时间；扫描后发生续租或换租约时不误回收。升级前遗留的无 token、无到期时间 `running` 也会被安全重排，避免永久阻塞账户。
- `pause`、`cancel` 会清理活动租约；`resume`、`retry` 从零重新排队并清理旧输出、错误、进度和执行时间，但保留原始输入。
- 新增可注入 `execute(task, context)` 的 `TaskRuntime`，默认全局并发 2、同账户并发 1、15 秒续租、1 秒兜底扫描；支持事件唤醒、受租约保护的 `reportProgress`、按任务中止以及幂等 `start()`/`stop()`。
- 将旧的设备心跳僵尸回收兼容入口改为仅依据任务租约过期回收，不再依赖 `devices` 表。

## 接口/数据/兼容性

- 数据迁移保留既有 `worker_device_id` 字段与旧数据，不删除表或历史输入。
- 首次迁移会将当时的遗留 `running` 任务重新排队；迁移记录写入后，重复启动不会再次重置后来正常运行的任务。
- 旧领取路由保留原 URL、认证和 `{ task }` 字段，同时在成功响应顶层新增 `leaseToken`；当账户已有有效运行任务时仍以既有 `409` 语义明确拒绝。
- `/progress` 请求体以及 `complete`/`fail` action 现在必须携带 `leaseToken`。这是最小但有意的安全协议收紧：旧版本桌面客户端因缺 token 会收到 `409`，不会继续无所有权写入。
- `/lease/renew` 请求体同样只接受领取响应返回的 `leaseToken`。该端点只续租，不发布 `task.updated`，避免 15 秒心跳形成无意义的 WebSocket 广播。
- 当前 `TaskCenter` 在领取响应后只把 token 保存在本次执行调用链内，依次传给 progress、complete、fail；token 不写入任务列表、不进入 WebSocket 广播，也不持久化到 UI 状态。
- 本批次没有自动执行真实任务；下一批次仍需把 HTTP/WS 控制 action 与 Runtime 中止/唤醒接起来，并接入真实执行器。

## 已知限制

- Runtime 尚未挂接真实 Coze/Agent Service，也未自动启动，客户端仍未切换到服务端执行主链路。
- 对外部生成服务而言，执行器可能已经产生不可逆副作用、但进程在写入完成状态前崩溃；租约恢复会从头执行，因此仍存在“外部副作用已发生但数据库未确认”的非幂等窗口。后续真实执行器需使用上游幂等键或结果对账机制收窄该窗口。
