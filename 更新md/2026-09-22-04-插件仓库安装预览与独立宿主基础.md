## 背景与目标

阶段四继续补齐插件中心。原有页面仍接 Mock Adapter，且顶栏“从来源安装”仅更新本地状态，尚未连接安装入口。本批次先实现后端真实数据与执行基础，为后续项目版本启停、权限代理和页面接线提供已验证接口。

用户已要求暂不处理图片/视频生成额度及效果，本批次没有调用媒体生成，也没有安装或执行未知第三方插件。执行测试使用本地编写的测试包。

### 文件及数据

- 按账户和 SHA-256 存储真实文件，不能以同一版本替换不同内容。
- 项目必须属于当前账户；绑定精确安装标识、版本、权限和配置。
- 仍被项目或当前运行组合引用的包拒绝卸载。
- 未引用包转入逻辑隔离，字节保留在内容仓库；30天到期清理，清理失败有持久错误记录并支持重试。
- 原 `plugin_manifests` 登记册不重建、不删除。
- 修复安装文件已经原子落盘、数据库尚未提交时的恢复路径：仅内容哈希仍匹配才允许登记。
- 路径穿越、Windows备用数据流、设备名、符号链接、重复或大小写冲突文件、超限包均拒绝。

### 安装及来源

- 解析来源不执行代码。npm tag/range 固定为精确版本并核对 tarball 完整性；GitHub ref 固定为具体 commit。
- 本地包校验上传字节哈希；压缩输入限16MB，解压后限32MB、1000个文件。
- 安装必须与预览账户、内容、版本及确认项一致；签名校验失败不能降级为未签名继续。
- 已配置受信公钥时支持签名验证；未签名和弱隔离等确认保持独立。
- 构建和健康探测是必经边界。构建执行器尚未配置时，带依赖或脚本的包返回 `BUILD_UNAVAILABLE`，不会被当作已经构建完成。

### 宿主执行

- 实际启动 Node 子进程，使用最小环境、受限文件读取及默认拒绝网络/子进程等权限。
- JSON Lines 消息带协议版本、运行组合标识、请求 ID 和能力令牌；单条消息限制256KB。
- 不继承主服务密钥；项目能力请求交回父进程 broker，宿主不持有数据库对象。
- 挂起超时、主动崩溃、无效协议和超量输出均局部终止，不直接终止主服务。
- 已验证“预览 → 确认 → 真实子进程健康检查 → 文件仓库提交”的本地测试包流程。

## 接口/数据/兼容性

新类初始化时增量创建 `plugin_packages`、`project_plugin_bindings`、`plugin_generations`、`plugin_events`、`plugin_data_quarantine`、`plugin_install_previews`。这些服务尚未挂接正式 HTTP 路由，所以主数据库和正式页面没有被切换为半成品运行时。

新增固定依赖：ajv 8.20.0、semver 7.8.5、tar 7.5.22、yauzl 3.4.0；锁文件将现有 multer 更新到2.4.0、qs到6.16.0，解决依赖审计发现的漏洞，未运行安装脚本。现有附件与服务端测试随后全量通过。

插件宿主要求 Node 支持 `--permission` 和网络权限控制。本机 Node v25.9.0 已实测；缺少相应能力时返回 `HOST_RUNTIME_UNSUPPORTED`，不静默以无限制进程运行。核心 Web 原有版本边界未改变，Electron 运行插件尚未验收。

Node 权限模型不是恶意代码强沙箱，因此安装预览始终如实报告 `strongSandboxAvailable=false`，不把进程隔离测试当作完整安全沙箱证明。依据：[Node 官方权限说明](https://nodejs.org/api/permissions.html)。
