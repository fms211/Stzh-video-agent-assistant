# 2026-08-11 · Agent 服务与附件持久化（于 2026-08-23 完成验收）

## 本次解决什么

将桌面端直连、不可复现的生成调用拆成可注入的服务端 Agent 核心，并建立“用户附件 → 任务绑定 → 队列执行器”的安全数据链。它是可靠任务运行时正式接线前的基础批次，不涉及界面视觉重做。

## 已落地能力

- 新增 `server/agent-service.js`：统一处理 Coze Chat、文件上传、SSE 分块解析、文本/媒体结果、超时和 abort。
- `/api/agent` 与 `/api/agent/stream` 共用该服务；测试可通过 `app.locals.agentService` 或显式 factory 注入 mock。
- 缺少 `COZE_API_TOKEN` 或 `COZE_BOT_ID` 时在发请求前返回 `MISSING_CONFIG`，即使全局 `fetch` 被包装也不会外连。
- 已有 `conversationId` 会作为远端取消兜底；获得 `chatId` 后取消最多请求一次 `/v3/chat/cancel`，取消失败不覆盖本地取消语义。
- 新增附件表、附件清理队列及安全清理租约：文件使用服务端随机名保存到 `attachments/<userId>/`，任务只能通过数据库绑定解析文件。
- 上传先登记可恢复的清理队列，再写文件；半批失败时使用注入的删除器回收。若磁盘锁定，队列保留记录并在下次清理重试，不会产生“数据库不知道的孤儿文件”。
- 清理附件前会写入原子 `cleanup_token`；清理期间不能绑定、解析或重试该附件所在的终态任务，过期 claim 可恢复。
- 附件大小以 `Buffer.length` 为准，声明大小不一致直接拒绝；目录、用户目录和文件本身均拒绝符号链接/junction 跳出附件根目录。
- 同一 `idempotencyKey` 只有 `kind`、标题、输入、来源、定时值、附件集合的规范化语义完全一致时才返回原任务；不同载荷返回 `409 IDEMPOTENCY_PAYLOAD_MISMATCH`，不绑定新附件。
- 恢复精简的 `opc-agent-api.ts` / `opc-agent-persist.ts` 数据层，并让创意助手在本地先持久化、登录后增量同步；访客只使用本地仓，不会发 OPC 同步请求。

## 数据与兼容性

- 新表：`task_attachments`、`attachment_cleanup_queue`；为既有附件表补充 `cleanup_token`、`cleanup_started_at`，不删除已有附件记录。
- 清理队列仅保存服务端生成的相对存储名、用户 ID、失败信息和 claim，不暴露本地绝对路径。
- 省略 `attachmentIds` 和明确传入空数组在旧任务的幂等重试中等价。
- 本批不新增依赖。`@langchain/langgraph` 属于后续/并发的创意工作流批次，不属于本次 Agent 与附件实现。

## 仍未完成的边界

- `TaskRuntime` 尚未由 `server.js` / Electron 启动入口创建，也尚未接管桌面主聊天；下一批会将 `video.generate` 执行器接到运行时。
- 远端取消是已取得远端 chat 标识后的 best effort，不把第三方网络层误报为本地任务失败。
- 附件清理是后台能力；生产启动接线后需要定期调用它，并报告磁盘不可写等运维错误。

## 回滚

代码回滚不会主动删除附件或清理队列数据；如果必须回退，应先停止新运行时，再保留 SQLite 数据与 `attachments/` 目录，避免丢失待重试的安全回收记录。
