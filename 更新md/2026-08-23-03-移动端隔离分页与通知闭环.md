# 2026-08-23 · 移动端隔离、任务分页与通知闭环

## 目标

解决手机切换账户或服务器后离线任务串仓、任务历史加载不稳定、桌面通知只刷新本地缓存等实际联动问题。

## 已完成

- 手机离线任务和已配对设备 ID 按“规范化服务器 URL + userId”分仓。
- 切换服务器地址会清除当前服务器 token/userId 并要求重新登录；旧服务器的离线队列和设备 ID 不删除，切回原服务器、原账户后可恢复。
- 旧全局离线队列和设备 ID 只复制迁移到首次确认的账户仓，保留旧值，不向后续账户重复复制。
- 任务 API 新增稳定游标分页，排序键为 `updated_at DESC, id DESC`；保留 offset 兼容旧客户端。
- 桌面和手机任务列表均使用 `nextCursor` 加载更多，避免并发更新造成重复或跳项。
- `status=completed,failed,cancelled` 可正确查询历史归档，归档总数按筛选状态计算。
- 任务完成、失败和取消时，服务端使用确定性 ID 幂等创建账户通知，并通过 WebSocket 推送 `notification.created`。
- 桌面收到事件后重新拉取服务端通知；localStorage 仅作为离线缓存。全部已读和清空操作同步服务端。
- 手机统一把通知 ID 视为字符串，将 SQLite unixepoch 秒正确转换为 ISO 时间，并在实时事件后重新拉取。

## 测试

- 手机服务器 A/账户 A 与服务器 B/账户 B 的离线任务、设备 ID 互不串仓，切回后数据可恢复。
- 游标两页无重复、非法游标 400、多终态归档结果和总数正确。
- 终态通知账户隔离、同一状态重复回调不重复写入。
- 桌面/手机通知都以服务端同步方法处理 WebSocket 事件。
- 当前根项目 P0 28/28、服务端 82/82；Web 与 Expo TypeScript 均通过。

## 回滚

回滚不会删除新的分仓键或旧全局键。旧客户端仍可使用 offset API；若回滚客户端，服务端新增的 `nextCursor` 字段不会破坏旧响应解析。
