# 创意工坊上下文公共层

当前供离线评测和四模式服务端请求构建使用；账户级HTTP/SQLite记忆、来源校验、项目笔记及按轮次摘录已接入，详见 `docs/knowledge/studio-memory-api.md`。部署默认`shadow`，构建拟用上下文但不改写实际模型请求；真实模型质量与灰度仍未验收。

`index.cjs` 是无数据库、网络、浏览器和第三方依赖的纯函数实现，类型在 `index.d.cts`。模式名沿用 Web 的 `coze / assistant / workflow / collaboration`；旧 OPC 的 `chat` 在后续 adapter 中映射为 `assistant`。

## 使用边界

- 服务端先鉴权，读取当前有效记录、作用域、来源、证据及附件权限，再调用 `selectMemories` 或 `buildStudioContext`。身份、确认状态和记录不能直接来自请求体。`authorize` 必须同步明确返回 `true`，同时确认记录仍存在且 revision 最新；省略、异步或其他返回值均拒绝。
- 纯函数无法查数据库，不能证明任意传入记录可信。浏览器可以预览，不能替代服务端重新构建。删除和撤权后必须重新取数；本模块不缓存任何候选。集成时仍需验证真实账户权限与并发变更。
- 筛选先按ID确定最新版本并检查格式/同版本冲突，再对该版本查账户、范围和来源权限，之后检查状态、敏感性、过期、当前约束和相关度。若同ID有无法确定先后的版本，整组停止使用；坏的新副本不能让旧副本复活。范围、来源及核验字段使用白名单，不能在参考packet中夹带未定义的“已批准”等字段。重复ID不重复占用候选；这不是数据库整合幂等性的实现。
- `source.recordId` 是新增的必需来源入口；`slot` 可表示 `style/aspect` 等结构化偏好键。当前明确约束存在时，旧值整条排除。未建模的自然语言冲突尚不能自动理解。
- 用户确认只表示允许保存/使用。观察、机制、假说进入 Evidence；核验需要证据ID和时间；版本不匹配或未知时降为 stale。依赖证据的权限和有效性仍须由调用方检查。
- 参考材料只会生成 `trust=reference` 的独立 packet，JSON保留原文、来源、版本和未知项。最终消息 adapter 必须继续维持此边界，不能把这些文本拼成高优先级 system 指令。数据分区也不能保证模型完全免疫提示注入。

## 预算

规则、任务、当前约束、工具/审批状态和输出要求必须完整保留；超出预算返回 `ok=false` 且无可发送内容。可选记忆按相关度整条纳入或舍弃，不截掉来源/核验状态，不删除原始记录。

纯构建器对完整本地JSON取UTF-8字节数加16；服务端provider适配器还估算完整出站JSON，并按用户配置的模型窗口保留输出余量。这是保守字节估算，**不等于提供商实际 token 数**。Coze远端历史用量标记unknown。

九个分区名已固定。纯构建器只负责记忆packet；服务端上下文服务负责按需附上机制参考、近期会话摘录和项目笔记，不做模型生成摘要，也不删除原始历史。

## 复现

```powershell
node --test test/studio-context.test.js test/studio-retrieval.test.js test/studio-retrieval-corpus.test.js
node scripts/stage4-memory-eval.cjs
```

评测输入与标签分文件存放在 `test/fixtures/`，现为corpus v5，共43条人工合成样本，全部纳入回归。它覆盖负空间/留白、通用词抑制、明确拒绝旧偏好、前置和后置改稿替换与普通比较。脚本报告每项命中、误入、遗漏、匹配词项及按四模式分组的已展示前五条精度；不把这个固定小样本称为独立盲评或生产 Precision@5 门槛。

## 检索词汇的适用范围

`retrieval.cjs` 的 `creative-lexical-v5` 是确定性词项检索，包含7组受控创作概念：留白、水墨、慢动作、浅/深景深、高/低反差。当前请求明确拒绝或将旧风格替换为新风格时，旧肯定偏好不因词项重合而入选；旧记忆同样记载拒绝时仍可作为约束参考。词项索引版本仍为`creative-lexical-v3`：此次只改变选择规则，FTS的入库词项不变，不重建现有索引。领域词参照项目 `app/data/opc-knowledge.ts` 的创作目录；别名表是本项目检索配置，并非文章/PDF原文给出的分类。新增别名需要同时补正例、子串边界和易混淆负例。

- 原始中文采用相邻字片段，中英文先做NFKC归一化。通用创作词移除后保留分隔符，避免“制作视频”中的“作视”成为伪相关词。
- 英文别名按完整词边界匹配，多空格归一化；`ink washer` 不能作为 `ink wash`。不会把单色等同黑白、白色等同留白或slow等同慢动作。
- 查询和候选明确指出相反景深/反差时，单独共有的“景深/对比”不能使它们互相召回；同时询问两者的比较仍可取两者。当前明确说“不要浅景深”时，旧的肯定偏好会被过滤；这只是受控词项规则，不等于理解任意自然语言否定。结构化创作参数仍是更明确的覆盖依据。
- “把水墨改成油画”“从水墨换成油画”“水墨不要了，改用油画”“换掉水墨，用油画”识别旧项为明确替换；“比较水墨和油画”仍保留两项。复杂转折或隐含意图仍需独立质量评审。
- 别名只提供相关线索，不改写原文、不抹去否定、不提高核验级别。返回 `matchedTerms` 和 `retrievalVersion` 便于审计。
- 没有embedding、自动扩词或任意同义理解。仅含通用词的请求可能返回0条；这是一项保守取舍，不等于所有记忆都不相关。尚需真实匿名样本与独立评审衡量召回损失。
