# Tszh Remote · 维护与验收要求

本文是main移动端后续开发/验收要求（2026-10-02文档核对），不是已完成检查表。当前组件说明见[DESIGN.md](DESIGN.md)，源码启动见[README](README.md)。手机阶段5未验收，阶段4也尚未完成。

## 延续现有设计

使用深空、暖琥珀和新拟态结构，优先复用theme.ts与Neu系列组件。实际实现包含渐变、阴影、平台分支和固定色例外，不再把“禁止渐变/内阴影”“代码减少70%”等旧规范当当前事实。

新设计不应靠颜色单独表达任务状态、审批或错误；文本与控件状态需和服务器一致。发光层在需要时允许溢出，但不得牺牲点击目标、文字可读性或页面裁剪。

## 功能与账户要求

| 项目 | 验收目标 |
|---|---|
| 连接 | 清楚区分服务地址、登录、配对、WS连接和业务执行；不照搬开发机默认IP |
| 账户切换 | 旧请求/缓存不进入新服务器或新账户，设备与离线待发内容分仓 |
| 任务控制 | 状态合法，重复操作受控；重连后读取服务器结果 |
| 生成与重试 | 本地失败不证明外部未执行；结果未知时先读权威状态 |
| 通知/历史 | 对应当前账户，已读/清空/分页与离线缓存语义明确 |
| 草稿 | 输入、附件与失败改稿保留，不能用清空内容掩盖同步问题 |

API、服务端权限和媒体执行来源见[应用API](../API调用.md)；移动实现不自动继承Web每一条能力或密钥保护保证。

## 需要真实设备覆盖的体验

1. Android/iOS目标版本、不同屏幕与平板安全区，横竖屏和系统导航行为。
2. 系统文字放大、触屏、中文IME发送/换行、可读标签及焦点/读屏。
3. 相机扫码与拒绝权限、手动配对、深链恢复，通知能力按平台限制验证。
4. 断网、后端不可达、重连、App后台/前台和进程重启的任务/缓存恢复。
5. 动画长时间运行、低端设备性能、电量及减少动画/透明度的具体降级。
6. 真正的媒体播放/下载与链接失效；文本或模拟图片不替代真实结果。

不以固定缩放公式、单一设计宽度或桌面截图判定这些项通过。

## 构建和交付

Expo native、Expo Web和Capacitor是不同路径，分别记录环境、版本、命令、权限及产物。当前npm提供start/android/ios/web，Capacitor没有统一发布脚本。

保留历史设计/阶段记录，以当前源码和实际证据维护活跃说明。新功能的文档记录按用户指定时机生成，阶段4完整开发记录暂不生成。测试/构建不能替代设备和外部媒体验收，详见[验证指南](../docs/TESTING.md)。
