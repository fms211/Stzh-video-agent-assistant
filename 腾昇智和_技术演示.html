💡 WHY
为什么选 Next.js 16 + React 19？
Next.js 16 + React 19
生态最强 静态导出
React 19 生态最丰富（Three.js/R3F/GSAP 完美支持）。App Router + output:"export" 兼顾开发体验和部署灵活性。Tailwind CSS 4 原生集成。
Nuxt 4 + Vue 3
Vue 生态 3D 弱
Vue 3 优秀，但 Three.js/R3F 在 Vue 中的库支持远不如 React（react-three-fiber）。粒子星空需要大量额外适配。
纯 Vite SPA
轻量 无路由
极致轻量，但缺少文件路由、API 代理、Image 优化等内置能力。需要手动搭建大量基础设施。
结论：项目需要 Three.js + R3F 做粒子星空，React 生态是唯一选择。Next.js 静态导出模式完美适配 Electron 打包。
💡 WHY
为什么选 Three.js + GSAP + anime.js？
Three.js + R3F
WebGL React 集成
680 粒子 + 3D 星座连线需要 WebGL GPU 渲染。R3F 声明式写法 + drei 预制组件。CSS 3D / Canvas 2D 性能不足。
Babylon.js / CSS 3D
可行 生态弱
Babylon.js React 封装库社区远不如 R3F。CSS 3D Transform 无法处理 680 粒子实时动画。
GSAP timeline + anime.js
编排王 微交互
GSAP 处理复杂编排（恒星坍缩 10+ 步精确序列）。anime.js 处理轻量微交互（涟漪/弹性）。职责分离各取所长。
Framer Motion / 纯 CSS
可行 编排弱
Framer Motion 不支持 WebGL。纯 CSS @keyframes 无法做 timeline 级动画编排。
结论：WebGL (Three.js) 是粒子系统的唯一选择。GSAP timeline 是复杂动画编排的唯一选择。两者组合 = 视觉效果天花板。

💡 WHY
为什么选 JWT 而不是 Session？
JWT (JSON Web Token)
无状态 跨端通用
服务端无状态，Token 自包含用户信息。浏览器 / Electron / PWA 三端通用。10 年有效期减少频繁登录。
Session Cookie
简单 需状态
服务端存储 session。Electron 内嵌 Express 无持久化 store，跨域需额外配置 cookie。
OAuth 2.0
第三方登录 过度设计
本项目是内部工具，用户名密码注册足够。OAuth 需注册第三方应用 + 回调配置，复杂度不匹配。
结论：JWT 无状态 = 浏览器/Electron/PWA 通用。服务端无需 session store，Electron 天然兼容。

⑪

SSE 事件转发规则

Coze 事件后端处理转发给前端
conversation.message.deltarole=assistant && type=answerevent: delta → 逐 token 文本
conversation.message.completedtype=answer → parseCozeCard()暂存，等 chat.completed
conversation.message.completedtype=follow_upevent: follow_up → 追问建议
conversation.chat.completedextractMediaUrls()event: done → 最终结果
💡 WHY
为什么选 Coze 而不是直接调 Claude API？
Coze v3 Chat API
免费额度 工作流
智能体编排 + 知识库检索 + 工作流一站式。免费额度充足。SSE 流式 + follow_up 建议开箱即用。
Claude API (Anthropic)
质量最高 按量计费
最强对话模型。但按 Token 计费（视频生成场景消耗大），缺少知识库检索和工作流编排。
自建模型
完全控制 成本极高
训练自有视频生成模型需 GPU 集群 + 大量数据 + ML 团队。对初创项目是天文数字成本。
结论：Coze 提供「智能体 + 知识库 + 工作流」一站式方案，免费额度足够 MVP 阶段。未来可按需切换到 Claude API。

💡 WHY
为什么选 SQLite 而不是 PostgreSQL / MongoDB？
SQLite (better-sqlite3)
零配置 嵌入式
单文件数据库，无需安装服务。同步 API 代码简洁无 async 噪音。WAL 模式支持并发读写。Electron 打包随应用分发。
PostgreSQL
功能最全 需服务
企业级数据库，但需单独安装维护。单用户场景大材小用。对非技术用户部署成本高。
MongoDB
灵活 需服务
文档数据库 schema 灵活，但对话/消息是结构化关系数据，SQL 外键约束和事务更可靠。
结论：单用户/小团队场景，SQLite 零配置 + 嵌入式是最优解。未来用户量增长可平滑迁移到 PostgreSQL（SQL 兼容）。
